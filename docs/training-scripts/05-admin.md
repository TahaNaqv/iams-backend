# Script 05 — IT Admin walkthrough

**Audience:** IT admins, platform engineers, SREs · **Length:** ~15 min · **Pre-req:** script 01 + admin-guide.md

What an admin runs once for setup and what they touch day-to-day. Pairs with the [admin guide](../admin-guide.md) — this video is the *demo*, the guide is the *reference*.

---

| Time | Narration | On-screen |
|---|---|---|
| 0:00–0:30 | "This walkthrough is for platform and IT admins. We'll go from initial deployment through user management, SSO wiring, ERP integration, and the monitoring stack — about 15 minutes end to end." | Title card. |
| 0:30–2:00 | "Setup. IAMS ships as a docker-compose stack. Clone the repo, drop your `.env` next to `docker-compose.yml`, then `docker compose run --rm backend-blue python manage.py migrate && python manage.py seed_rbac`. The seed creates the 6 stock roles and 12 permission rows you need before the FE is usable." | Terminal recording: clone, env, migrate, seed_rbac. |
| 2:00–3:00 | "Bring the stack up with `docker compose --profile blue up -d`. The blue and green profiles are the deploy targets — `./deploy/blue_green.sh` swaps between them with migration-before-flip safety. nginx fronts both at the host network port." | docker compose up. `docker compose ps` → all healthy. |
| 3:00–4:00 | "Smoke test. `./deploy/smoke_test.sh` curls /health/, /ready/, /metrics, /api/schema/, the SPA index, and verifies `/api/audits/` returns 401 — that proves auth is wired. Six green checkmarks and you're production-ready." | Run smoke_test.sh. |
| 4:00–5:30 | "User management lives at *Settings → Users*. Create a user, assign a role, set the department. If you've enabled SSO, this is the *initial* role assigned to JIT-provisioned SSO users; admins can override later. Roles control everything via the permission matrix — see *Settings → Roles* to add or revoke permissions per role." | Create a user. Assign role Audit Manager. Show the resulting permission grid. |
| 5:30–7:30 | "SSO setup. Bring up Keycloak — in this demo we use the on-prem instance at keycloak.iams.internal. Create the `iams` realm. Federate AD via the LDAP provider. Create an OIDC client `iams-backend`, set redirect URIs to `https://iams.internal/api/auth/sso/callback/`. Add a groups mapper. Then in IAMS, set the OIDC_* env vars and `IAMS_SSO_ENABLED=true`, restart the backend." | Keycloak admin → realm → client config. Switch to IAMS .env → set vars → docker compose restart. |
| 7:30–8:30 | "Map Keycloak groups to IAMS roles. POST to `/api/sso/group-role-maps/` with the full group path and the IAMS role ID. Precedence — lower wins — handles users in multiple groups. Now your AD groups drive IAMS role assignment automatically on every sign-in." | curl example with the POST payload. Then a user sign-in showing the auto-assigned role. |
| 8:30–10:00 | "ERP integration. Open *Settings → Integrations*. Register a source — say, SAP. Generate a strong inbound secret; the SAP team configures their outbound to POST to `/api/integrations/webhooks/<source-id>/auditable-entities/` with an X-IAMS-Signature header. Watch the event ledger — every accepted or rejected delivery is rowed." | Create source. Curl a sample webhook. Open event ledger; show the accepted row. Show a tamper attempt → signature_invalid. |
| 10:00–11:00 | "Outbound user sync. Flip *Outbound enabled* and *Push users* on the HRIS source, set the URL and bearer token. Now every User.save() on IAMS triggers a POST to your HRIS with the user payload. Failures land in the event ledger as `failed` rows for retry — the admin decides whether to re-push." | Configure HRIS source. Create a test user. Show the outbound row in the ledger. |
| 11:00–12:30 | "Monitoring. Grafana dashboards live at `deploy/grafana/` — import `iams-system.json` and `iams-business.json`. System shows latency p50/95/99, error rate, DB pool, Celery queue depth, security panels. Business shows the live CAP overdue gauge, daily findings by severity, audit lifecycle." | Grafana → import dashboards → tour each panel. |
| 12:30–13:30 | "Alert rules. Drop `deploy/prometheus/iams-alerts.yml` into Prometheus's rules dir. Pageable: error rate > 1%, p95 > 1s, Celery backlog > 1000, lockout burst. Warn-level: failed login spike, report job failures, overdue CAP threshold. Route severity=page to PagerDuty, warn to Slack." | Open `iams-alerts.yml` in an editor. Show the AlertManager routing config. |
| 13:30–14:30 | "Backups. Cron `./deploy/backup.sh` nightly at 2 AM. pg_dump → MinIO mirror → age encryption → restic to NAS and offsite. Retention 7/4/12. Run the restore drill quarterly with `./deploy/restore.sh latest <target-db-url>` — don't trust an untested backup." | Cron entry. Show a successful run in the log. Restore drill on a replica. |
| 14:30–15:00 | "That's the admin tour. Detailed runbooks for each of these are in `docs/admin-guide.md`. Questions or platform issues, hit `#iams-platform` in Slack." | Outro card. |
